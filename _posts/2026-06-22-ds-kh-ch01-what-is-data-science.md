ស្វាគមន៍មកកាន់​មេរៀន​ដំបូង​នៃ​ស៊េរី​នេះ។ មុន​យើង​បាញ់​ចូល​បច្ចេក​ទេស, យើង​ត្រូវ​ឆ្លើយ​សំណួរ​មូលដ្ឋាន​មួយ៖ **តើ​ Data Science ជា​អ្វី?** សិស្ស​ច្រើន​ឆ្លើយ​ថា​ "មាន​ការ​ទាក់​ទង​នឹង​ AI" ឬ "មាន​ការ​ទាក់​ទង​នឹង​ Big Data" — ត្រូវ​មួយ​ផ្នែក, ប៉ុន្តែ​មិន​ច្បាស់​លាស់​គ្រប់​គ្រាន់​ឡើយ។ មេរៀន​នេះ​នឹង​ផ្តល់​ឱ្យ​អ្នក​នូវ​និយមន័យ​ដែល​ច្បាស់​លាស់ និង​មាន​ឧទាហរណ៍​ពិត​ប្រាកដ​ពី​ឧស្សាហកម្ម​នៅ​កម្ពុជា។

# សង្ខេប

- **Data Science** គឺ​ជា​វិទ្យាសាស្ត្រ​ដែល​ប្រើ​ទិន្នន័យ ​(data) ដើម្បី​ស្វែង​យល់​ពី​បាតុ​ភូត, ព្យាករ​អនាគត, និង​សម្រេច​ចិត្ត​បាន​ល្អ​ជាង​មុន
- វា​បង្កើត​ឡើង​ដោយ​ការ​បញ្ចូល​គ្នា​នៃ​ **៣ ផ្នែក​**៖ **គណិតវិទ្យា / ស្ថិតិ**, **កុំព្យូទ័រ / ការ​សរសេរ​កម្មវិធី​**, និង​ **ចំណេះ​ដឹង​អំពី​វិស័យ​អាជីវកម្ម​** (domain knowledge)
- Data Science **មិន​ស្មើ​នឹង Excel** — វា​ឆ្លើយ​សំណួរ​ដែល Excel ឆ្លើយ​មិន​បាន (ឧ. ព្យាករ​អនាគត, រក​លំនាំ​ឆ្ងាយ​ៗ, ប្រើ​ទិន្នន័យ​ធំ​)
- ផល​ផ្ដល់​នៃ Data Science មាន ៣ ប្រភេទ៖
  1. **Descriptive** — ​អ្វី​បាន​កើត​ឡើង? (analytics)
  2. **Predictive** — ​អ្វី​នឹង​កើត​ឡើង? (machine learning)
  3. **Prescriptive** — ​យើង​គួរ​ធ្វើ​អ្វី? (optimization, A/B testing)

# ហេតុអ្វីសំខាន់?

កម្ពុជា​នៅ​ឆ្នាំ 2026 មាន​ទិន្នន័យ​ច្រើន​ជាង​ពេល​ណា​ៗ — Bakong មាន​ប្រតិបត្តិការ​រាប់​លាន​ដង​ក្នុង​មួយ​ខែ, Wing មាន​អតិថិជន​លើស​ពី​ ៩ លាន​នាក់, ACLEDA មាន​ប្រវត្តិ​កម្ចី​រាប់​លាន​សន្លឹក។ **ប៉ុន្តែ ទិន្នន័យ​មិន​ស្មើ​នឹង​ការ​យល់​ដឹង​ឡើយ**។

ស្ថាប័ន​ដែល​មាន​ទិន្នន័យ​ច្រើន​តែ​មិន​អាច​យល់​វា​បាន​ → ខាត​ឱកាស​អាជីវកម្ម។ ស្ថាប័ន​ដែល​មាន​ Data Scientist ល្អ → អាច​ផ្លាស់​ប្ដូរ​ទិន្នន័យ​ទៅ​ជា **ការ​សម្រេច​ចិត្ត​​មាន​លុយ​ចូល​មក​វិញ**។

**ឧទាហរណ៍​ស្រាល៖** ACLEDA ផ្ដល់​កម្ចី​ ​\$2,000 ​ដល់​អ្នក​លក់​ដូរ​នៅ​ផ្សារ​ដើម​គរ។

- **គ្មាន Data Science**៖ មន្ត្រី​ឥណទាន​ប្រើ​ "feeling" និង​ឯកសារ​សាមញ្ញ​ (ID, ប្លង់​អាជីវកម្ម) → ការ​សម្រេច​ចិត្ត​ឋាន​ខ្ពស់, កម្ចី​ខូច (NPL) ច្រើន
- **មាន Data Science**៖ ប្រើ​លំនាំ​ដែល​យក​ទិន្នន័យ​ប្រតិបត្តិការ​ Wing, កម្ចី​មុន​ៗ, លំនាំ​សេវា​ទូរស័ព្ទ ​→ ការ​ព្យាករ​ហានិភ័យ​ប្រសើរ​ជាង​មុន 25–30% → ​​ប្រាក់​ចំណេញ​បន្ថែម​​រាប់​លាន​ដុល្លារ​ក្នុង​មួយ​ឆ្នាំ

**Data Science មិន​មែន​ជា​ "luxury" — ​វា​ក្លាយ​ជា​តម្រូវ​ការ​មូលដ្ឋាន​សម្រាប់​ស្ថាប័ន​ដែល​ចង់​ប្រកួត​ប្រជែង​ក្នុង​សតវត្ស​ទី ២១។**

# គំនិតវិចារណញ្ញាណ

## Data Science = ការ​ស៊ើប​អង្កេត​ដែល​ដឹក​នាំ​ដោយ​ទិន្នន័យ

ស្រមៃ​អ្នក​ស៊ើប​អង្កេត​ (detective) មួយ​នាក់​នៅ​កន្លែង​ប្លន់៖
- គាត់​ប្រមូល​ **ភ័ស្តុតាង** (data) — ស្នាម​ជើង, ប្រូ​ភិល​សម្លេង, គន្លឹះ​ផ្សេងៗ
- គាត់​ប្រើ​ **ការ​សម្គាល់​លំនាំ** (pattern recognition) — ប្រូ​ភិល​នេះ​ឯក​សាន​នឹង​ករណី​មុន​ៗ​យ៉ាង​ណា?
- គាត់​ផ្ដល់​ **ការ​សន្និដ្ឋាន** (inference) — តើ​អ្នក​ប្លន់​នោះ​ជា​អ្នកណា?
- គាត់​ឆ្ពោះ​ទៅ​ **ការ​សម្រេច​ចិត្ត** — តើ​ត្រូវ​ចាប់​អ្នកណា?

Data Scientist ធ្វើ​ដូច​ស៊ើប​អង្កេត​ដែរ — **ប៉ុន្តែ​ប្រើ​ទិន្នន័យ​ប្រេប​ប៉ុនណា​ហើយ​ប្រេប​អ្វី​យ៉ាង​ច្បាស់**៖

| ស៊ើបអង្កេត | Data Scientist |
|---|---|
| ស្នាម​ជើង | ទិន្នន័យ​ប្រតិបត្តិការ |
| ប្រូភិល​សម្លេង | លំនាំ​ប្រវត្តិ​អតិថិជន |
| គន្លឹះ​ផ្សេងៗ | ទិន្នន័យ​ខាង​ក្រៅ (អាកាសធាតុ, តម្លៃ​ទីផ្សារ​) |
| ការ​សន្និដ្ឋាន | លទ្ធផល​គំរូ​ ML |
| ការ​ចាប់​អ្នកប្លន់ | ការ​សម្រេច​ចិត្ត​អាជីវកម្ម |

## បី​ផ្នែក = មួយ​អ្នក

Data Science មិន​មែន​ជា​ផ្នែក​ NEW។ វា​ជា​ "intersection" (ការ​ប្រសព្វ​គ្នា) នៃ​ ៣ ផ្នែក​ដែល​មាន​ស្រាប់​៖

**១. គណិត​ / ស្ថិតិ​** — ដើម្បី​យល់​ថា​លេខ​មាន​ន័យ​អ្វី
- ​បើ​អ្នក​មាន​ទិន្នន័យ​ទម្ងន់​សិស្ស​ ៥០ ​នាក់​ ហើយ​មធ្យម 55 kg, តើ​សិស្ស​ម្នាក់​ដែល​ទម្ងន់​ 80 kg គឺ​ "ខុស​ធម្មតា" ឬ​ទេ?
- ស្ថិតិ​ប្រាប់​យើង​បាន​ប្រាកដ — ​ដោយ​ប្រើ​ស្តង់ដារ​ឌីវី​យ៉ាស្យុង។

**២. កុំព្យូទ័រ​ / ការ​សរសេរ​កម្មវិធី​** — ដើម្បី​ដោះ​ស្រាយ​ទិន្នន័យ​ច្រើន​លឿន
- ទិន្នន័យ​ ៥០ ជួរ → Excel ដោះ​ស្រាយ​បាន
- ទិន្នន័យ​ ៥​ លាន​ជួរ → ត្រូវ​ Python, SQL, ឬ​ Spark

**៣. ចំណេះ​ដឹង​អំពី​វិស័យ​អាជីវកម្ម​** (domain knowledge) — ដើម្បី​ឆ្លើយ​សំណួរ​ត្រឹមត្រូវ
- ​ប្រសិន​បើ​អ្នក​មិន​ស្គាល់​វិស័យ​មីក្រូ​ហិរញ្ញវត្ថុ, អ្នក​នឹង​ផ្ដោត​លើ​អថេរ​មិន​ត្រឹមត្រូវ
- ​ប្រសិន​បើ​អ្នក​មិន​ស្គាល់​របៀប​លក់​ស្រូវ​នៅ​បាត់ដំបង, គំរូ​ព្យាករ​ផល​ស្រូវ​នឹង​ខុស

**ការ​បាត់​ផ្នែក​ណា​មួយ​ = មិន​មែន​ជា Data Scientist។**

![Venn diagram of Data Science](/images/ds-series/ch01-what-is-data-science.svg)

> តើ​អ្នក​ខ្លាំង​គណិត​ ស្ថិតិ​ + ខ្លាំង​សរសេរ​កម្មវិធី​ ប៉ុន្តែ​មិន​យល់​វិស័យ​អាជីវកម្ម​? → អ្នក​ជា **ML Engineer / Researcher**
> តើ​អ្នក​ខ្លាំង​សរសេរ​កម្មវិធី​ + យល់​វិស័យ​ ប៉ុន្តែ​មិន​ខ្លាំង​ស្ថិតិ​? → អ្នក​ជា **Data Engineer / Software Engineer**
> តើ​អ្នក​ខ្លាំង​ស្ថិតិ​ + យល់​វិស័យ​ ប៉ុន្តែ​មិន​សរសេរ​កម្មវិធី​? → អ្នក​ជា **Statistician / Business Analyst**
> តើ​អ្នក​ខ្លាំង​ទាំង​បី? → អ្នក​ជា **Data Scientist** 🎯

# និយមន័យ និងខ្លឹមសារ​សំខាន់

## និយមន័យ​ផ្លូវការ

> **Data Science គឺ​ជា​វិទ្យាសាស្ត្រ​ និង​សិល្បៈ​នៃ​ការ​យក​ទិន្នន័យ​មក​ផ្លាស់​ប្ដូរ​ជា​ការ​យល់​ដឹង​ (insight) និង​ការ​សម្រេច​ចិត្ត​ (decision) ​ដែល​មាន​តម្លៃ​ដល់​អង្គភាព​មនុស្ស​ ឬ​អង្គភាព​អាជីវកម្ម​។**

ឬ​សាមញ្ញ​ជាង​នេះ៖

> **Data → Insight → Decision**

|---|---|---|
| **Descriptive** (សង្ខេប) | តើ​អ្វី​បាន​កើត​ឡើង? | របាយការណ៍​លក់​ប្រចាំ​ខែ |
| **Diagnostic** (រក​មូលហេតុ) | ហេតុ​អ្វី​បាន​ជា​កើត? | ហេតុ​អ្វី​ការ​លក់​ធ្លាក់​ចុះ​ខែ​មីនា? |
| **Predictive** (ព្យាករ) | តើ​អ្វី​នឹង​កើត? | ការ​លក់​ខែ​ក្រោយ​នឹង​យ៉ាង​ណា? |
| **Prescriptive** (ផ្ដល់​យោបល់) | យើង​គួរ​ធ្វើ​អ្វី? | ត្រូវ​បញ្ចុះ​តម្លៃ​ប៉ុន្មាន​ដើម្បី​បង្កើន​ការ​លក់? |

**ការ​ឡើង​ឋាន​ៗ៖** ស្ថាប័ន​ជា​ច្រើន​នៅ​កម្ពុជា​ឋិត​នៅ​ត្រឹម​កម្រិត​ Descriptive (​Excel ​សង្ខេប​) ​ប៉ុណ្ណោះ​។ ផ្លាស់​ប្ដូរ​ទៅ Predictive ឬ Prescriptive ​នឹង​ផ្ដល់​អត្ថ​ប្រយោជន៍​ខ្ពស់​ខ្លាំង។

## Data Science vs ការ​បកស្រាយ Excel ធម្មតា

នេះ​ជា​ការ​ប្រៀបធៀប​ដែល​សិស្ស​យល់​ច្បាស់​បំផុត៖

| លក្ខណៈ | Excel Reporting | Data Science |
|---|---|---|
| **ទំហំ​ទិន្នន័យ** | ≤​ 100,000 ជួរ | រាប់​លាន​ឬ​ច្រើន​ជាង |
| **សំណួរ​សំខាន់** | "តើ​ខែ​មុន​លក់​ប៉ុន្មាន?" | "តើ​អតិថិជន​ ​នេះ​នឹង​បាក់​ខែ​ក្រោយ​ឬ​ទេ?" |
| **ឧបករណ៍** | Excel, Google Sheets | Python, R, SQL, Jupyter |
| **​ការ​ធ្វើ​ឡើង​វិញ** | ដោយ​ដៃ​ម្ដង​មួយ​​ខែ | ស្វ័យ​ប្រវត្តិ​រាល់​ថ្ងៃ​ឬ​ម៉ោង |
| **ប្រភេទ​ផល​ផ្ដល់** | តារាង, pivot table | គំរូ​ ML, dashboard live |
| **ភាព​ជឿ​ជាក់** | មនុស្ស​បកស្រាយ​មាន​អត្តាន្តមតិ | ស្ថិតិ​ផ្ដល់​កម្រិត​ជឿ​ជាក់ (confidence interval) |
| **ការ​ព្យាករ** | ផ្អែក​លើ​អារម្មណ៍​ឬ trend line | គំរូ​ ML ​ដែល​បង្ហាត់​ដោយ​ទិន្នន័យ​មុនៗ |

> **កុំ​យល់​ខុស​៖** Data Science **​មិន​ជំនួស** Excel ទេ — Excel នៅ​តែ​មាន​ប្រយោជន៍​សម្រាប់​ការ​ងារ​សាមញ្ញ។ Data Science ​ឆ្លើយ​សំណួរ​ដែល Excel ​ឆ្លើយ​មិន​បាន។

# ឧទាហរណ៍កម្ពុជា

យក​មក​ ៥ ឧទាហរណ៍​ពិតៗ​នៅ​កម្ពុជា ដែល Data Science ​មាន​ការ​ប្រើ​ប្រាស់​ច្បាស់​ហើយ៖

## ឧទាហរណ៍ ១៖ ACLEDA Bank — ការ​ផ្ដល់​ពិន្ទុ​ឥណទាន (Credit Scoring)

**បញ្ហា៖** ACLEDA ផ្ដល់​កម្ចី​​មីក្រូ​​ដល់​អតិថិជន​ដែល​មិន​មាន​ប្រវត្តិ​ធនាគារ​ (unbanked)​។ មន្ត្រី​ឥណទាន​ត្រូវ​សម្រេច៖ "តើ​ត្រូវ​ផ្ដល់​កម្ចី​នេះ​ឬ​ទេ?"

**វិធី​សាស្ត្រ​ Data Science៖**
- ប្រមូល​ទិន្នន័យ​ប្រវត្តិ​អតិថិជន​ ៥ ឆ្នាំ​មុន​ (កម្ចី​ប៉ុន្មាន, បាន​សង​ឬ​មិន​សង)
- ​បន្ថែម​ទិន្នន័យ​ខាង​ក្រៅ​ — ប្រូ​ភិល​ការ​ប្រើ​ប្រាស់ Wing, ទីតាំង​អាជីវកម្ម
- បង្ហាត់​ឱ្យ​គំរូ​ logistic regression ឬ gradient boosting ឱ្យ​ព្យាករ​ "ប្រូបាប៊ីលីតេ​បាក់​"
- ​មន្ត្រី​ឥណទាន​ប្រើ​ពិន្ទុ​ជា​ឧបករណ៍​ជំនួយ​ — មិន​មែន​ជា​ការ​ជំនួស​ការ​សម្រេច​ចិត្ត​ឡើយ

**លទ្ធផល​ស្រដៀង​​**ដែល​ឃើញ​នៅ​ឧស្សាហកម្ម​មីក្រូ​ហិរញ្ញវត្ថុ​អន្តរជាតិ៖ NPL (កម្ចី​ខូច) ​ធ្លាក់​ចុះ ​២០–៣០%, ល្បឿន​អនុម័ត​លឿន​ ៥–១០ ដង។

## ឧទាហរណ៍ ២៖ Wing Mobile Money — ការ​រក​ការ​ក្លែង​បន្លំ (Fraud Detection)

**បញ្ហា៖** ៩+ លាន​អតិថិជន​ × ប្រតិបត្តិការ​រាប់​លាន​ដង​ក្នុង​មួយ​ថ្ងៃ → អ្នក​​ផ្ទៀង​ផ្ទាត់​ដោយ​ដៃ​មិន​អាច​ធ្វើ​បាន​ឡើយ។

**វិធី​សាស្ត្រ Data Science៖**
- រក​ "លំនាំ​ប្រតិបត្តិការ​ធម្មតា" របស់​អតិថិជន​ម្នាក់​ៗ​
- ដាក់​ "ការ​ព្រមាន​"​ នៅ​ពេល​ប្រតិបត្តិការ​ខុស​ពី​ធម្មតា​ច្រើន — ឧ. ផ្ទេរ​ \$5,000 ទៅ​លេខ​មិន​ធ្លាប់​មាន​នៅ​ ៣ ​យប់ (អតិថិជន​ធម្មតា​ផ្ទេរ​ \$20 ទៅ​ក្រុម​គ្រួសារ​ប៉ុណ្ណោះ)
- ផ្អាក​​ប្រតិបត្តិការ​ដោយ​ស្វ័យ​ប្រវត្តិ​ → ហៅ​អតិថិជន​ផ្ទៀង​ផ្ទាត់​

**លទ្ធផល​​៖** អ្នក​ក្លែង​បន្លំ​ច្រើន​ត្រូវ​ចាប់​បាន​​ក្នុង​រយៈ​ពេល​ខ្លី — សន្សំ​អតិថិជន​ពី​ការ​បាត់​បង់​លុយ​​​។

## ឧទាហរណ៍ ៣៖ ការ​ព្យាករ​ផល​ស្រូវ​នៅ​ខេត្ត​បាត់ដំបង

**បញ្ហា៖** កសិករ​ខ្មែរ​ច្រើន​ត្រូវ​ការ​ដឹង​មុន​ថា​ ​ផល​ស្រូវ​​ឆ្នាំ​នេះ​នឹង​បាន​ប៉ុន្មាន — ​ដើម្បី​សម្រេច​ចិត្ត​ខ្ចី​ឬ​ទេ, ដាំ​ស្រូវ​ប្រភេទ​អ្វី។

**វិធី​សាស្ត្រ Data Science៖**
- ប្រមូល​ទិន្នន័យ​ ​​​៥–១០ ​ឆ្នាំ​​៖ បរិមាណ​ភ្លៀង, សីតុណ្ហភាព, ប្រភេទ​ដី, ប្រភេទ​ស្រូវ, ផល​ដែល​បាន​មុនៗ
- បន្ថែម​ទិន្នន័យ​ផ្កាយ​រណប (NASA MODIS, Sentinel-2) — សុខភាព​ដី​ឃើញ​ពី​លើ​អាកាស
- បង្កើត​គំរូ​ ​ML — input: អាកាសធាតុ​​ + ដី → output: ​ផល​ស្រូវ tons/hectare
- បង្ហាញ​លទ្ធផល​ដល់​កសិករ​តាម​ App (Khmer language)

**លទ្ធផល​​៖** កសិករ​ដឹង​មុន​ឱ្យ​សម្រេច​ចិត្ត​បាន​​ល្អ​ — បន្ថយ​ហានិភ័យ, បង្កើន​ប្រាក់​ចំណូល។

## ឧទាហរណ៍ ៤៖ Smart / Cellcard — ការ​ព្យាករ​ការ​ផ្ដាច់​សេវា (Churn Prediction)

**បញ្ហា៖** ការ​ទាក់​ទាញ​អតិថិជន​ថ្មី​ថ្លៃ​ ​៥–៧ ដង​នៃ​ការ​រក្សា​អតិថិជន​ចាស់​។ ​ផ្ដាច់​សេវា​ (churn) = ​បាត់​លុយ​ច្រើន​​។

**វិធី​សាស្ត្រ Data Science៖**
- រក​លំនាំ​អតិថិជន​ដែល​ច្រើន​តែ​ផ្ដាច់​មុន​ផ្ដាច់ — ឧ. ការ​ហៅ​ទូរស័ព្ទ​ធ្លាក់​ចុះ​ ៥០% ​ក្នុង​មួយ​ខែ​មុន
- បង្កើត​គំរូ ML ​ដែល​ផ្ដល់ "probability of churn" សម្រាប់​អតិថិជន​ម្នាក់​ៗ​
- បញ្ជូន​ការ​ផ្ដល់​ជូន​ពិសេស​ (data bonus, ការ​ហៅ​ឥតគិតថ្លៃ​) ដល់​អ្នក​មាន​ហានិភ័យ​​ខ្ពស់​ — មុន​ពួក​គេ​​ផ្ដាច់

**លទ្ធផល​​៖** អត្រា churn ​ធ្លាក់​ចុះ​ ១៥–២៥%, ប្រាក់​ចំណូល​បន្ត​មាន​ស្ថេរ​ភាព។

## ឧទាហរណ៍ ៥៖ Nham24 — ការ​ព្យាករ​តម្រូវ​ការ​ ​​និង​ផ្លូវ​ដឹក​ជញ្ជូន

**បញ្ហា៖** តើ​ត្រូវ​មាន​ Driver ប៉ុន្មាន​នាក់​នៅ​តំបន់​ទួលគោក​​ម៉ោង​ល្ងាច​ថ្ងៃ​សុក្រ?

**វិធី​សាស្ត្រ Data Science៖**
- ​យក​ទិន្នន័យ​ប្រវត្តិ​៖ ​​បញ្ជា​ទិញ​ច្រើន​ប៉ុនណា​នៅ​តំបន់​នេះ, ​ម៉ោង​ណា, ​ថ្ងៃ​ណា
- ​បន្ថែម​ទិន្នន័យ​ផ្សេង​ៗ៖ ​​​អាកាសធាតុ, ការ​ប្រាក់​បុណ្យ, ការ​បិទ​ផ្លូវ
- គំរូ​ time-series ​​ព្យាករ​ ​"ការ​បញ្ជា​​ទិញ​ម៉ោង​ខាង​មុខ​"
- ​ប្រើ algorithm route optimization ​(​ដូច Google Maps) ​ដើម្បី​បែង​ចែក Driver
- Driver ​ផ្ដល់​ស្ថានភាព​ល្អ → អតិថិជន​​ទទួល​អាហារ​​ឆាប់ → អតិថិជន​ត្រឡប់​មក​ប្រើ​ម្ដង​ទៀត

# លំហាត់

## លំហាត់ ១៖ ការ​បែងចែក​ – Descriptive, Predictive, ឬ Prescriptive?

សម្រាប់​សំណួរ​នី​មួយ​ៗ​ខាងក្រោម — តើ​វា​ជា Descriptive, Diagnostic, Predictive, ឬ Prescriptive?

a) ខែ​មុន ACLEDA ​ផ្ដល់​កម្ចី​ប៉ុន្មាន​ដុល្លារ?
b) ខែ​ក្រោយ ACLEDA នឹង​ផ្ដល់​កម្ចី​ប៉ុន្មាន?
c) ​ហេតុ​អ្វី​បាន​ជា​ការ​លក់​ខែ​មីនា​ធ្លាក់​ចុះ?
d) ត្រូវ​​បញ្ចុះ​តម្លៃ​ស្រូវ​ប៉ុន្មាន​ភាគរយ​ដើម្បី​​បំបាត់​ស្តុក​ឱ្យ​អស់​ត្រឹម​ខែ​ក្រោយ?
e) តើ​អតិថិជន Smart ដែល​មាន​ឈ្មោះ​លេខ 1234 ​មាន​ហានិភ័យ​ផ្ដាច់​សេវា​ប៉ុនណា?

<details>
<summary>ចម្លើយ</summary>

a) **Descriptive** — ឆ្លើយ "​អ្វី​បាន​កើត​ឡើង"
b) **Predictive** — ​ឆ្លើយ "​អ្វី​នឹង​កើត"
c) **Diagnostic** — ​ឆ្លើយ "​ហេតុ​អ្វី​បាន​ជា​កើត"
d) **Prescriptive** — ឆ្លើយ "​យើង​គួរ​ធ្វើ​អ្វី"
e) **Predictive** — ឆ្លើយ "​អតិថិជន​នេះ​មាន​ឱកាស​​​​ផ្ដាច់​ប៉ុនណា"

</details>

## លំហាត់ ២៖ ផ្នែក​ណា​នៃ​​ Venn?

​សម្រាប់​​បុគ្គល​នី​មួយ​ៗ​ — តើ​គាត់​ជា Data Scientist, ML Engineer, Data Engineer, ឬ Business Analyst?

a) ​ភី​បាន​បរិញ្ញាបត្រ​​គណិតវិទ្យា, ​ខ្លាំង Excel ​នឹង Power BI ប៉ុន្តែ​មិន​ចេះ Python
b) ​សុ​​ភ័ក្រ្ត​ខ្លាំង Python, ​ស្គាល់ AWS, បាន​​ការ​សិក្សា​ផ្នែក IT ​ប៉ុន្តែ​មិន​យល់​អ្វី​ដែល​ធ្វើ​ឱ្យ​ការ​លក់​​ឡើង​ឬ​ចុះ
c) ​ដារ៉ា​បាន​បរិញ្ញាបត្រ​​ស្ថិតិ, ​ខ្លាំង Python + SQL, ​ធ្វើ​ការ​នៅ​ ACLEDA ​បាន ​៣​ ​ឆ្នាំ​ហើយ​ស្គាល់​វិស័យ​ហិរញ្ញវត្ថុ​ច្បាស់
d) ​សុខា​ខ្លាំង​សរសេរ​កម្មវិធី​ + ខ្លាំង​គណិតវិទ្យា​ ML, ​ប៉ុន្តែ​ធ្វើ​ការ​ជា​ ​​contractor ​ផ្លាស់​ប្ដូរ​វិស័យ​រាល់​​ ​៦​ ​ខែ

<details>
<summary>ចម្លើយ</summary>

a) **Business Analyst** — ​ស្ថិតិ ✓ + ​វិស័យ ✓, ​ប៉ុន្តែ​បាត់​ Coding
b) **Data Engineer / Software Engineer** — Coding ✓, ​ប៉ុន្តែ​បាត់ ​Domain Knowledge
c) **Data Scientist** ✓✓✓ — ​មាន​ទាំង​បី​ផ្នែក​​ច្បាស់
d) **ML Engineer / Researcher** — Coding ✓ + ​ស្ថិតិ ✓, ​ប៉ុន្តែ​បាត់ ​Domain Knowledge

</details>

## លំហាត់ ៣៖ ​​​ការ​គិត​ស្រាវ​ជ្រាវ​

​​ស្រមៃ​ថា​អ្នក​​ធ្វើ​ការ​នៅ​​សហ​គ្រិន ​e-commerce ​មួយ​នៅ​កម្ពុជា​ (​ដូច Smile Shop)។ ចៅហ្វាយ​សួរ​អ្នក​សំណួរ​ ​៣ ​ឆ្នាំ​នេះ៖

i. "តើ​យើង​មាន​អតិថិជន​ប៉ុន្មាន​​ដែល​​មិន​បាន​ទិញ​អ្វី​​ ​​៣ ​ខែ​ហើយ?"
ii. "តើ​​ការ​ផ្ញើ​ការ​ជូន​ដំណឹង​ (notification) ​ផ្ដល់​​លុយ​ដល់​យើង​ប៉ុនណា?"

សម្រាប់​សំណួរ​នី​មួយ​ៗ៖
- ​ត្រូវ​ការ​ទិន្នន័យ​អ្វី?
- វា​ជា​ Descriptive, Predictive ​ឬ Prescriptive?
- ​អ្នក​ប្រើ​ឧបករណ៍​អ្វី? (Excel, Python, SQL, Tableau, ...)

<details>
<summary>ចម្លើយ​សំណូ​មពរ</summary>

**សំណួរ​ ​i:**
- ​ទិន្នន័យ៖ ​ប្រវត្តិ​​បញ្ជា​ទិញ​​អតិថិជន​ (orders table) ​ជាមួយ ​user_id ​និង​​កាល​បរិច្ឆេទ
- ​ប្រភេទ៖ ​**Descriptive** — រាប់​ចំនួន​​អតិថិជន​ដែល​​ប្រវត្តិ​​ចុង​ក្រោយ > ៣ ​ខែ​មុន
- ​ឧបករណ៍៖ ​**SQL** ​ឬ ​**Excel pivot** — ​អាស្រ័យ​លើ​ទំហំ​​ទិន្នន័យ

**សំណួរ​ ​ii:**
- ​ទិន្នន័យ៖ ​ការ​ផ្ញើ notification (កាល​បរិច្ឆេទ, ​user_id), ​បញ្ជា​ទិញ​ (កាល​បរិច្ឆេទ, ​user_id, ទឹក​លុយ), ​អថេរ​បន្ថែម​ (ប្រូ​ដ្យួ​ត, តម្លៃ)
- ​ប្រភេទ៖ ​**Diagnostic** ​ឬ ​**Prescriptive** — ​​ត្រូវ​ការ ​A/B test (ផ្ញើ​ដល់​ ​៥០% ​នៃ​អតិថិជន, ​ប្រៀបធៀប​នឹង​អ្នក​មិន​ទទួល​)
- ​ឧបករណ៍៖ ​**Python + Pandas** ​សម្រាប់​​ការ​វិភាគ, ​**SQL** ​ដើម្បី​​ទាញ​​​ទិន្នន័យ​, ​ស្ថិតិ (t-test) ​ដើម្បី​ផ្ដល់​កម្រិត​ជឿ​ជាក់

</details>

# សង្ខេប​ឱ្យ​ខ្លី

🎯 **ផល​ផ្ដល់​មាន ​៣–៤ ​​ប្រភេទ៖** Descriptive → Diagnostic → Predictive → Prescriptive។
