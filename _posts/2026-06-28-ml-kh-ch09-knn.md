# សង្ខេប

- **Algorithm**៖ store training data → ​សម្រាប់ $x$ ​ថ្មី → ​ស្វែង​រក $k$ neighbors ជិត​បំផុត → vote/average
- **Classification**៖ $\hat y(x) = \arg\max_c \sum_{i \in N_k(x)} \mathbb{1}[y_i = c]$
- **Regression**៖ $\hat y(x) = \dfrac{1}{k} \sum_{i \in N_k(x)} y_i$
- **Distance metrics**៖ Euclidean ($L_2$), Manhattan ($L_1$), Minkowski ($L_p$), Cosine
- **$k$ ​តូច** → bias ​ទាប, variance ​ខ្ពស់ (overfit); **$k$ ​ធំ** → bias ​ខ្ពស់, variance ​ទាប (underfit)
- **Weighted KNN**៖ $w_i \propto 1 / d(x, x_i)$ — neighbor ​ជិត​​ឱ្យ​ vote ​ច្រើន
- **Lazy learner**៖ training time = O(1), prediction time = O(nd) (brute force)
- **Curse of dimensionality**៖ $d$ ​ធំ → ​ចំណុច​​ទាំង​អស់​ស្មើ​ចម្ងាយ → "neighbor" ​​​មិន​មាន​ន័យ
- **​ត្រូវ standardize** ​មុន — distance ​ឆ្លុះ​ feature scale!

**ឧស្សាហកម្ម​នៅ​កម្ពុជា​ដែល​ប្រើ​ផ្ទាល់​៖**

- **PP house price** — ​ព្យាករ​ផ្ទះ​ដោយ​មើល 5 ​ផ្ទះ​ដែល​ស្រដៀង​បំផុត (sqm, ​ខណ្ឌ, ​អាយុ) → KNN regression

- **Crop yield** — farm ​ដែល​ស្រដៀង​នៅ​ខែ​ដំណាល​​ ​ឆ្នាំ​មុន → ​ព្យាករ​ផ្ទាល់

**ច្បាប់​ស្នូល​៖** KNN ​មាន​​​អំណាច​ **ច្បាស់​ៗ​នៅ​ low dimension** ​(d < 20) — ​អ្នក​អាច​បង្ហាញ​ business stakeholder ដោយ​ប្រាប់​ "​ផ្ទះ​ស្រដៀង​ 5 ​ដំបូង​មាន​តម្លៃ​ប្រហែល \$300K" — explainable ​​ខ្លាំង។ ​ប៉ុន្តែ​នៅ high dimension (d > 50) → ​​ខូច​ខ្លាំង — ​ត្រូវ​ DR (មេរៀន 20-23) ​មុន។

# គំនិត​វិចារណញ្ញាណ

## "​ប្រាប់​ខ្ញុំ​អ្នក​​​ស្និទ្ធ​ស្នាល 5 នាក់ — ​ខ្ញុំ​ប្រាប់​អ្នក​ជា​​នរណា"

ច្បាប់​ស្នូល​​នៃ KNN — ​​​​​​​អ្នក​ស្រដៀង​នឹង​​​​អ្នក​ដែល​​​នៅ​ជិត​អ្នក។ ​បើ 4 / 5 ​មនុស្ស​ស្និទ្ធ​ស្នាល​​​ជា​សិស្ស​ engineering → ​​អ្នក​​ប្រហែល​ engineer ​ដែរ។

## "​មិន​​​មាន​ training" — ​អ្វី​ដែល​មាន​ន័យ?

​​​​Linear regression, ​​Ridge — ​​​​​​​មាន "training" ​ច្បាស់៖ ​ដោះ​ស្រាយ​ optimization ​ដើម្បី​បាន $w^*$ → keep $w^*$ → ​បោះ data ​ចេញ​ក៏​បាន។

KNN ​ផ្ទុយ — **​​ស្រូប​​​ data ​ទាំង​អស់ ​មិន​ដោះ​ស្រាយ​អ្វី​សោះ**។ ​នៅ​ពេល prediction — ​ស្វែង​រក $k$ ​ចំណុច​ជិត​បំផុត → vote/average។

**Trade-off៖**
- Training: O(1) (​ត្រឹម​តែ​ store)
- Prediction: O(nd) brute force ​​ ​​​​​​(​ត្រូវ​​​គណនា​ distance ​ទៅ​ training points ​ទាំង​អស់)
- Memory: O(nd) ​(​ត្រូវ​​​​ store ​ទាំង​អស់)

## "$k$ ​តូច = ​ ​ត្រួត​ត្រា​ច្បាស់, ​​ខ្លាំង​​​​ប៉ុន្តែ​ ​​​ងាយ​ខូច" 

- $k = 1$ → ​ស្ថិត​ស្ថេរ​លើ noisy point → ​ភ្ជាប់​ outlier → decision boundary ​​ច្រែក​ច្រាន​មិន​ស្រួល
- $k = n$ → ​ឱ្យ​ majority class ​ទាំង​អស់ → ​ចំ​លើយ​ដូច​គ្នា​សម្រាប់​ $x$ ​ទាំង​អស់ → ​ឥត​ប្រយោជន៍
- ​​ល្អ​បំផុត​​នៅ​មធ្យម — ​ច្បាស់​ $k = 5$ ​ឬ $k = 10$ — ​ត្រូវ​​ប្រើ CV ​ដើម្បី​ជ្រើស

## "Distance metric ​ត្រូវ​​ត្រូវ"

- ​​សម្រាប់​ feature ​លេខ (price, sqm) — Euclidean
- ​​សម្រាប់​ binary feature (gender, owns_car) — Hamming ​ឬ Manhattan
- សម្រាប់ text/document vector — Cosine (មិន​ឱ្យ​ document ​វែង​ឆ្ងាយ​ ​ឆ្ងាយ​​ច្បាស់ — ​​​​​​​​​​​​​​​​​​​មើល​ angle)
- សម្រាប់ time series — DTW (Dynamic Time Warping)

# និយមន័យ និង​គណិតវិទ្យា

## ១. KNN Algorithm (formal)

**Input**៖ training set $\mathcal{D} = \{(x_i, y_i)\}_{i=1}^n$, query $x$, hyperparameter $k$, distance metric $d$.

**Step 1**៖ Compute $d(x, x_i)$ for all $i = 1, \ldots, n$.

**Step 2**៖ Sort distances, ​ជ្រើស​ indices ​នៃ $k$ ​​​​​តូច​បំផុត — $N_k(x) = \{i_1, \ldots, i_k\}$.

**Step 3 (classification)**៖

$$
\hat y(x) = \arg\max_{c \in \mathcal{C}} \sum_{i \in N_k(x)} \mathbb{1}[y_i = c]
$$

**Step 3 (regression)**៖

$$
\hat y(x) = \frac{1}{k} \sum_{i \in N_k(x)} y_i
$$

## ២. Distance metrics

### Euclidean ($L_2$)

$$
d_2(x, x') = \sqrt{\sum_{j=1}^d (x_j - x'_j)^2} = \|x - x'\|_2
$$

​​ច្បាស់, ​សាមញ្ញ, ​ស្តង់​ដារ​សម្រាប់​ feature ​លេខ​​​បន្ទាប់​ពី standardization។

### Manhattan ($L_1$)

$$
d_1(x, x') = \sum_{j=1}^d |x_j - x'_j| = \|x - x'\|_1
$$

​​ប្រើ​នៅ​ពេល feature ​មាន​ structure ​ដូច​ផ្លូវ​ក្នុង PP (taxi cab — ​​មិន​ត្រូវ​បោះ​​ក្នុង building)។

### Minkowski ($L_p$)

$$
d_p(x, x') = \left( \sum_{j=1}^d |x_j - x'_j|^p \right)^{1/p}
$$

ទូទៅ: $p = 1 \Rightarrow L_1$, $p = 2 \Rightarrow L_2$, $p \to \infty \Rightarrow$ Chebyshev (max coordinate diff).

### Cosine

$$
\cos\theta(x, x') = \frac{x \cdot x'}{\|x\|_2 \|x'\|_2}, \quad d_\text{cos} = 1 - \cos\theta
$$

​សម្រាប់ text/document — ​​មិន​ឱ្យ document ​វែង​ឆ្ងាយ ​​ឆ្ងាយ​ច្បាស់ ​— ​​​មើល​​​ direction ​ត្រឹមតែ​។

## ៣. Weighted KNN

​​ឱ្យ neighbor ​ជិត ​​ vote ​ច្រើន​ជាង neighbor ឆ្ងាយ​៖

$$
\hat y(x) = \frac{\sum_{i \in N_k(x)} w_i \cdot y_i}{\sum_{i \in N_k(x)} w_i}, \quad w_i = \frac{1}{d(x, x_i) + \epsilon}
$$

($\epsilon$ ​តូច​ការ​ពារ​​ ​​division by zero ​ពេល $x = x_i$)

​សម្រាប់​ classification ​​​​​​​​—​​ vote ​​ដោយ weight៖

$$
\hat y(x) = \arg\max_c \sum_{i \in N_k(x)} w_i \cdot \mathbb{1}[y_i = c]
$$

## ៤. ​ហេតុ​​អ្វី standardize ​​សំខាន់?

​ឧបមា​ feature៖
- $x_1$ = sqm of house (range: 50–500)
- $x_2$ = number of bedrooms (range: 1–6)

​​បើ​មិន standardize → distance ​ឆ្លុះ​​ $x_1$ ​ស្ទើ​ទាំង​អស់ — $x_2$ ​ប្រហែល​ឥត​មាន​ឥទ្ធិពល។

**​ច្បាស់​ច្នេះ**៖ ​ស្តង់​ដារ​មុន KNN៖

$$
x_j \leftarrow \frac{x_j - \mu_j}{\sigma_j}
$$

(​ដោយ $\mu_j, \sigma_j$ ​​​បាន​ពី training data) — ​បន្ទាប់​ពី standardization, ​​​​feature ទាំង​អស់​​​មាន scale ​ដូច​គ្នា (mean = 0, std = 1)។

## ៥. Curse of dimensionality

​​បើ​ $d$ ​ធំ → ​ចំណុច​ទាំង​អស់​ស្មើ​ចម្ងាយ​​​​​​​ច្បាស់​ៗ​!

ឱ្យ​ random points uniform in $[0, 1]^d$។ ​​​សម្រាប់ query $x$ random​៖

$$
\frac{d_\max - d_\min}{d_\min} \to 0 \quad \text{ដោយ} \quad d \to \infty
$$

→ "​​ចំណុច​ជិត​បំផុត" ​ដូច "​ចំណុច​ឆ្ងាយ​បំផុត" ​ច្បាស់ — KNN ​ឥត​មាន​ន័យ​ទៀត​ឡើយ​​!

**​ច្បាប់​ឧស្សាហកម្ម​៖**
- $d < 10$ — KNN ​​ខ្លាំង
- $d \in [10, 50]$ — KNN ​​ត្រូវ ​​​ ​​​ស្តង់​ដារ + ​​​ការ​ជ្រើស feature ​​​​ល្អ
- $d > 50$ — ​​ត្រូវ DR (PCA, autoencoder) មុន KNN

## ៦. Computational concerns

Brute-force prediction = O(nd) per query → ​យឺត​ខ្លាំង​​នៅ​ពេល $n$ ​ធំ។

**Data structures ​ដែល​​ល្អ​​ជាង​៖**

- **kd-tree** — ​​​​បំ​បែក space ​ដោយ axis-aligned splits → query O($\log n$) ​ល្អ​បំផុត, ​​មិន​ល្អ​ពេល $d > 20$
- **Ball-tree** — ​​​​បំ​បែក​​ដោយ spheres → ​​ល្អ​ជាង​ high-d
- **LSH (Locality-Sensitive Hashing)** — approximate nearest neighbor → O(1) ​​​​​​​​​​​​​​សម្រាប់ $d$ ​​ធំ​ខ្លាំង
- **FAISS** (Facebook) — production-scale nearest neighbor library

      var u = 0, v = 0;

# ឧទាហរណ៍

## ឧទាហរណ៍ 1៖ KNN classification ​ដោយ​ដៃ

ឱ្យ training data​៖

| $i$ | $x_1$ | $x_2$ | class |
|---|---|---|---|
| 1 | 1 | 2 | A |
| 2 | 2 | 3 | A |
| 3 | 3 | 1 | A |
| 4 | 6 | 5 | B |
| 5 | 7 | 7 | B |
| 6 | 8 | 6 | B |

​ព្យាករ class ​នៃ query $x = (5, 4)$ ​ដោយ $k = 3$, Euclidean distance.

**Step 1**៖ Distance ​ពី $x = (5, 4)$ ​ទៅ​​ training point ​នី​មួយ​ៗ​៖

| $i$ | $d(x, x_i)$ | class |
|---|---|---|
| 1 | $\sqrt{(5-1)^2 + (4-2)^2} = \sqrt{20} \approx 4.47$ | A |
| 2 | $\sqrt{9 + 1} = \sqrt{10} \approx 3.16$ | A |
| 3 | $\sqrt{4 + 9} = \sqrt{13} \approx 3.61$ | A |
| 4 | $\sqrt{1 + 1} = \sqrt{2} \approx 1.41$ | B |
| 5 | $\sqrt{4 + 9} = \sqrt{13} \approx 3.61$ | B |
| 6 | $\sqrt{9 + 4} = \sqrt{13} \approx 3.61$ | B |

**Step 2**៖ ​ជ្រើស 3 ​​​​​តូច​បំផុត — $i = 4$ (1.41), $i = 2$ (3.16), tie ​​​​​​​​​​​​នៅ​​ $i = 3, 5, 6$ ​​​​​​​ដែល​មាន distance 3.61។ ​​​​ឱ្យ​ tie-breaking ​ដោយ​ឯករា​ជ្យ — ​ឧបមា​ជ្រើស $i = 3$។

→ 3-NN = $\{4, 2, 3\}$ ​​​​​មាន​ class $\{B, A, A\}$

**Step 3**៖ Vote — A: 2, B: 1 → $\hat y(x) = A$.

## ឧទាហរណ៍ 2៖ KNN regression — house price

ឱ្យ​ training​៖

| House | sqm | Bedrooms | Price (\$K) |
|---|---|---|---|
| 1 | 100 | 2 | 80 |
| 2 | 150 | 3 | 120 |
| 3 | 200 | 4 | 180 |
| 4 | 120 | 2 | 95 |
| 5 | 180 | 3 | 150 |

​ព្យាករ​ price ​នៃ​ផ្ទះ​​ថ្មី sqm = 140, bedrooms = 3, $k = 3$ ​​បន្ទាប់​ពី standardization.

**Standardize**៖ $\mu_\text{sqm} = 150, \sigma_\text{sqm} \approx 39.4$; $\mu_\text{bed} = 2.8, \sigma_\text{bed} \approx 0.84$

| House | $z_1$ (sqm) | $z_2$ (bed) | Price |
|---|---|---|---|
| 1 | -1.27 | -0.95 | 80 |
| 2 | 0 | 0.24 | 120 |
| 3 | 1.27 | 1.43 | 180 |
| 4 | -0.76 | -0.95 | 95 |
| 5 | 0.76 | 0.24 | 150 |

Query: $z = (-0.25, 0.24)$

| House | distance | Price |
|---|---|---|
| 1 | 1.71 | 80 |
| 2 | 0.25 | 120 |
| 3 | 1.99 | 180 |
| 4 | 1.27 | 95 |
| 5 | 1.01 | 150 |

3-NN = $\{2, 5, 4\}$ → $\hat y = (120 + 150 + 95) / 3 = \$121.67K$.

## ឧទាហរណ៍ 3៖ Weighted KNN

​ដូច​ឧទាហរណ៍ 2, ​ប៉ុន្តែ​ដាក់ weight $w_i = 1 / d_i$៖

| House | $d$ | Price | $w = 1/d$ | $w \cdot \text{price}$ |
|---|---|---|---|---|
| 2 | 0.25 | 120 | 4.00 | 480.0 |
| 5 | 1.01 | 150 | 0.99 | 148.5 |
| 4 | 1.27 | 95 | 0.79 | 75.1 |

$\sum w = 5.78$, $\sum w \cdot \text{price} = 703.6$

$$
\hat y = \frac{703.6}{5.78} \approx \$121.7K
$$

​ស្រដៀង​បន្តិច​ ​ប៉ុន្តែ​ ​ផ្ទះ 2 ​ដែល​ស្និទ្ធ​បំផុត ​មាន​ឥទ្ធិពល 68% — ​​​ ​ច្បាស់​ខ្លាំង​ជាង uniform KNN!

# លំហាត់

### លំហាត់ 1 — KNN ​ដោយ​ដៃ

ឱ្យ training​៖

| $i$ | $x$ | $y$ |
|---|---|---|
| 1 | 1.0 | 2.0 |
| 2 | 2.0 | 4.0 |
| 3 | 3.0 | 5.0 |
| 4 | 4.0 | 4.5 |
| 5 | 5.0 | 7.0 |

​ព្យាករ $\hat y$ ​នៅ $x = 3.5$ ​ដោយ KNN regression, $k = 3$.

<details markdown="1">
<summary><strong>បង្ហាញ​ចម្លើយ</strong></summary>

Distance ​ពី $x = 3.5$៖

| $i$ | $\|x_i - 3.5\|$ | $y_i$ |
|---|---|---|
| 1 | 2.5 | 2.0 |
| 2 | 1.5 | 4.0 |
| 3 | 0.5 | 5.0 |
| 4 | 0.5 | 4.5 |
| 5 | 1.5 | 7.0 |

3-NN = tie ​នៅ $i = 3, 4$ (distance 0.5), ​ហើយ $i = 2$ ​ឬ $i = 5$ (distance 1.5 ​ស្មើ​គ្នា)។ ​​​​ឱ្យ​ tie-breaking ​ដោយ​ឯករា​ជ្យ — ​ឧបមា​ជ្រើស $i = 2$ (smaller index)។

→ 3-NN = $\{3, 4, 2\}$ → $\hat y = (5.0 + 4.5 + 4.0) / 3 = 4.5$

**Weighted KNN**៖ $w_i = 1/d_i$ → $w_3 = w_4 = 2$, $w_2 = 0.667$

$$
\hat y = \frac{2 \cdot 5.0 + 2 \cdot 4.5 + 0.667 \cdot 4.0}{2 + 2 + 0.667} = \frac{21.668}{4.667} \approx 4.64
$$

</details>

### លំហាត់ 2 — Bias–variance ​ដោយ $k$

​ដាក់ scenarios ​ខាង​ក្រោម — តើ $k$ ​​​ល្អ​បំផុត​ប្រហែល​ប៉ុនមាន?

(a) Training data ​ច្បាស់​​ ​ឥត​មាន noise, $n = 1000$<br>
(b) Training data noisy ​ខ្លាំង, $n = 100$<br>
(c) Training data ស្មុគ​ស្មាញ + ​ច្បាស់​ៗ, $n = 10000$<br>
(d) Training data noisy + $n = 30$

<details markdown="1">
<summary><strong>បង្ហាញ​ចម្លើយ</strong></summary>

**ច្បាប់​ស្នូល​៖**
- Noise ​ខ្ពស់ → $k$ ​ត្រូវ​​​ធំ​ដើម្បី average ​ឆ្លុះ noise
- $n$ ​ធំ → $k$ ​អាច​​​ធំ​​ ​ដោយ​ឥត​បាត់ "local pattern"
- $n$ ​​​​​តូច + noisy → ​ត្រូវ​​​ប្រយ័ត្ន, ​ច្បាស់ overfit ​ងាយ

**(a)** $k$ ​​​​​តូច (1–3) — ​ឥត​មាន noise → ​​មិន​ត្រូវ average

**(b)** $k$ ​មធ្យម (15–30) — ​ត្រូវ average noise; ​មាន $n = 100$ ​​​អាច​យក $k$ ​​​ធំ​បាន

**(c)** $k$ ​​​​​តូច​ត្រឹម (3–7) — pattern ​ស្មុគ​ស្មាញ​ត្រូវ​ការ resolution; $n$ ​ធំ → local pattern ​ច្បាស់

**(d)** $k$ ​មធ្យម (5–10) — ​ត្រូវ​សុំ​​ noise ​ប៉ុន្តែ​ $n$ ​​​​​តូច → $k = 30$ ​នឹង average ​​​ច្រើន​ខ្លាំង → ​ត្រូវ CV ​ច្បាស់!

</details>

### លំហាត់ 3 — Curse of dimensionality

​ឧបមា​ random points uniform ​ក្នុង $[0, 1]^d$, $n = 1000$ points។ ​សួរ​៖

(a) ​​​ដោយ $d = 1$ — ​​ប្រហែល​​​ "​​​ ​បរិមាណ​ unit hypercube"​​​​?<br>
(b) ​​​ដោយ $d = 10$ — ​បរិមាណ?<br>
(c) ​ហេតុ​អ្វី KNN ​​ដំណើរ​​ការ​ខ្សោយ​​ខ្លាំង​នៅ​ $d = 10$ ​បើ​​មាន​បរិមាណ "​​​ល្អ​"?

<details markdown="1">
<summary><strong>បង្ហាញ​ចម្លើយ</strong></summary>

**(a)** Volume ​នៃ $[0, 1]^1 = 1$

**(b)** Volume ​នៃ $[0, 1]^{10} = 1^{10} = 1$ (​ដូច​គ្នា!)

**(c)** **ច្បាស់​ច្នេះ​៖** ​​​បរិមាណ​សរុប​​​ ​ដូច​គ្នា ​ប៉ុន្តែ​ density ​ដួល​យ៉ាង​​ឆាប់​៖

- $d = 1$: 1000 points ​​ឆ្លងកាត់​ 1D segment → ​​​ស្ទើ​ៗ​​​ neighbor 0.001 ​ឆ្ងាយ
- $d = 10$: 1000 points ​ឆ្លងកាត់​ 10D cube → ​សម្រាប់​ neighbor ​នៅ​ចម្ងាយ $r$, ​បរិមាណ​​ដែល​​ neighbor ​ស្ថិត​ក្នុង = $r^{10}$
   - ​​ ដើម្បី​មាន 5 neighbors → $r^{10} \cdot 1000 = 5 \Rightarrow r = (5/1000)^{1/10} \approx 0.59$
- → ​​"5 neighbor ​ជិត​​បំផុត" ​​​នៅ​​​​​ ​​​ស្ទើ​ 60% ​នៃ​ data range — **​ឥត​មែន "ជិត" ​សោះ​!**

​ច្បាស់​ច្នេះ — ​​នៅ $d$ ​ធំ → ​ត្រូវ data exponential ($n \propto k^d$) ​ដើម្បី​​​បាន density ​ដូច​ low-d → **​ឥត​អាច​ច្នេះ ​ច្បាស់​ៗ​​**។

</details>

### លំហាត់ 4 — Distance metric ​ត្រូវ​ជ្រើស

ឱ្យ scenarios — ​ជ្រើស distance metric ​ល្អ​បំផុត​៖

(a) Khmer news article ​ដើម្បី classify category<br>
(b) ​ផ្ទះ​ក្នុង PP — sqm, bedrooms, ​ខណ្ឌ<br>
(c) Time series — ប្រាក់​ដាក់​ ATM ​ប្រចាំ​ថ្ងៃ ​ឆ្នាំ 2025<br>
(d) Genome sequence — DNA strings ប្រវែង 1000

<details markdown="1">
<summary><strong>បង្ហាញ​ចម្លើយ</strong></summary>

**(a) Cosine** — TF-IDF vectors, ​​​មិន​ឱ្យ document ​វែង​ឆ្ងាយ​ច្បាស់; ​មើល direction (topic) ត្រឹម​តែ

**(b) Euclidean ​បន្ទាប់​ពី standardization** — feature ​លេខ​​ច្រើន​​ scale ​ខុស; standardize ​មុន ​ហើយ​ប្រើ $L_2$

**(c) DTW (Dynamic Time Warping)** — time series ​ដែល​​​​​ "​​ ​ឆ្លុះ" ​នៅ​ពេល​ខុស​បន្តិច → DTW ​អនុញ្ញាត time shift; Euclidean ​​មិន​ឱ្យ shift → ​ចំណាញ់​

**(d) Hamming ​ឬ​ edit distance** — ​​ត្រូវ​ការ​ probability ​ដែល​​ position ​ដូច​គ្នា; edit distance ​ឱ្យ insertion/deletion (mutation)

</details>
